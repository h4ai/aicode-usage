# 配额口径从"日对话上限"迁移为"当日 Token 限额"

## 1. 需求背景

- **目标**：将系统日配额口径从"对话/请求次数"统一迁移为"Token 使用量"，以更贴近实际 LLM 资源消耗，实现更精准的费控管理
- **成功标准**：
  - 管理员后台"当日 Token 限额"可正常配置并触发超限拦截
  - 个人看板展示"当日 Token 数"（K/M 缩写格式），且口径与配额一致
  - 非限额时段查看看板时展示 Tooltip 说明
  - 邮件通知按 Token 口径正常触发（阈值策略不变）
  - 月度配额及其他链路不受影响
  - 历史数据保留，旧字段标记 `deprecated`
- **范围边界**：
  - 仅变更**日度配额**口径（日对话上限 → 当日 Token 限额）
  - 月度 Token 配额口径维持不变，不在本次变更范围内
  - **降级服务为远期规划，本期不实现**
  - 变更对齐文档：`docs/requirements.md`（v0.7）四/六/七章节；`docs/requirements-quota-email-v2.md`（v0.3）日度配额项

## 2. 需求描述

- **功能概述**：对系统中所有涉及"日对话上限/每日请求次数/今日对话次数/daily_chats"的配置项、展示指标、邮件通知口径，统一替换为基于【工作日 + 限额时段（09:00–12:00、13:00–18:00）】内 Token 使用量的新口径
- **业务价值**：Token 口径更真实反映 LLM 资源消耗，便于成本分摊与精细化管控；消除"水量不同的对话按次数等价"的口径偏差
- **核心场景**：
  1. 管理员为配额级别配置"当日 Token 限额"，用户在工作日限额时段内达到限额后请求被拦截
  2. 用户在个人看板查看自己当日已消耗 Token 数及占比进度
  3. 系统在用户 Token 消耗达到阈值（50% / 80% / 100%）时发送邮件告警
- **统计口径规则**（已确认）：
  - 统计维度：用户（user）
  - 时区：Asia/Shanghai（固定）
  - 工作日：周一至周五，暂不考虑法定节假日
  - 限额时段：09:00–12:00、13:00–18:00
  - **Token 归属时间**：按**请求发起时间**判定；跨时段边界的请求（如 17:59 发起、18:03 返回）按发起时间归属，计入限额时段
  - 统计范围：**仅计入**落在【工作日 + 限额时段】内的 Token；周末与非限额时段 Token **完全不计入**
  - Token 字段：ClickHouse `totalToken`（若现有报表使用其他公式，以代码实现为准）

## 3. 用户旅程

- **主要用户**：管理员、普通用户（员工）

- **主路径 A — 管理员配置配额**：
  1. 管理员进入「管理员后台 → 配额级别」
  2. 选择或新建配额级别
  3. 找到"当日 Token 限额"字段（原"日对话上限"）
  4. 输入整数 Token 值并保存
  5. 配额级别即时生效，用于超限判断

- **主路径 B — 用户使用超限**：
  1. 用户在工作日限额时段内使用 AI 编码功能
  2. 当日【工作日+限额时段】Token 消耗达到配额限额（消耗值 >= 限额）
  3. 系统拒绝后续请求并返回超限提示（降级服务本期不实现）
  4. 次日 00:00（Asia/Shanghai）配额重置

- **主路径 C — 用户查看个人看板（限额时段内）**：
  1. 用户在工作日限额时段内打开个人看板
  2. 查看"当日 Token 数"进度条（格式：120K / 1.2M）及百分比
  3. 口径与配额判断一致（仅工作日+限额时段）

- **主路径 D — 用户查看个人看板（非限额时段）**：
  1. 用户在周末或 18:00 后打开个人看板
  2. 展示"当日 Token 数"，同时显示 Tooltip：「当前为非限额时段，此时段使用不计入当日配额」
  3. 数值仅反映当日限额时段内的消耗，不含非限额时段使用量

- **主路径 E — 邮件告警**：
  1. 系统监测用户当日 Token 消耗
  2. 达到阈值（50% / 80% / 100%）时触发邮件
  3. 邮件内容：已用 Token（K/M 格式）、Token 限额、使用占比、次日重置时间
  4. 去重策略与发送时机沿用现有策略

- **异常路径**：
  - 管理员输入非整数或超大值 → 前端校验提示，沿用现有配额级别编辑校验逻辑
  - 非工作日 / 非限额时段使用 → Token 不计入当日消耗，不触发超限，个人看板数值不变
  - 月度 Token 超限 → 沿用现有月度配额逻辑，不受本次变更影响

## 4. 页面结构

### 4.1 管理员后台 — 配额级别

- **列表页**：原"日对话上限"列改为"当日 Token 限额"，单位显示为 Token
- **详情页**：同步替换字段文案，明确单位
- **编辑页**：
  - 字段标签：当日 Token 限额
  - 输入类型：整数（需支持较大数值）
  - 单位说明：Token（仅统计工作日限额时段内使用量）
  - 校验规则：沿用现有配额级别编辑逻辑
- **API 字段**：相关字段命名同步切换（例如 `daily_token_limit`），避免旧字段名语义漂移

### 4.2 个人看板 — 今日指标

- **指标卡替换**：
  - 原：今日对话次数
  - 新：当日 Token 数
- **进度条**：显示当日 Token 消耗 / 当日 Token 限额（百分比）
- **数值展示格式**：缩写形式（如 `120K`、`1.2M`）
- **非限额时段 Tooltip**：当用户在非限额时段（周末 / 18:00 后 / 12:00–13:00）查看时，显示说明：「当前为非限额时段，此时段使用不计入当日配额」

### 4.3 邮件通知

- **文案替换**：将次数口径相关文案替换为 Token 口径（已用 Token、Token 限额、使用占比）
- **占位符**：沿用模板结构，替换为 Token 字段
- **数值格式**：建议 K/M 缩写显示
- **重置时间说明**：次日 00:00 Asia/Shanghai（自然日周期，统计仅覆盖限额时段）
- **阈值**：沿用现有实现（已实现 [50, 80, 100] 则适用；仅实现 80% 则保持一致）

## 5. 输入输出

### 5.1 输入

| 场景 | 输入 | 说明 |
|------|------|------|
| 管理员配置配额 | 整数 Token 值 | 当日 Token 限额，替换原日对话上限 |
| 用户发起 AI 请求 | 请求内容 + 发起时间 | 按**发起时间**判断是否属于限额时段，统计 totalToken |
| 查看个人看板 | 页面访问 + 当前时间 | 触发当日【工作日+限额时段】Token 聚合查询；当前时间用于判断是否展示 Tooltip |
| 邮件告警触发 | 系统定时/实时计算 | Token 消耗 / Token 限额 达到阈值档位 |

### 5.2 输出

| 场景 | 输出 | 说明 |
|------|------|------|
| 配额保存成功 | 成功提示 + 列表刷新 | 新 Token 限额即时生效 |
| Token 超限 | 请求被拒绝 + 超限提示 | 降级服务本期不实现；行为与次数超限一致 |
| 个人看板（限额时段内） | 当日 Token 数 + 进度条（K/M 格式） | 仅统计工作日限额时段内 Token |
| 个人看板（非限额时段） | 同上 + Tooltip 提示 | 「当前为非限额时段，此时段使用不计入当日配额」 |
| 邮件告警 | 告警邮件 | 含已用 Token（K/M）、限额、占比、重置时间 |
| 配额重置 | 次日消耗归零 | 00:00 Asia/Shanghai 按自然日重置 |

## 6. 验收标准

| 模块 | 验收项 |
|------|--------|
| 管理后台 | 配额级别页面展示"当日 Token 限额"，可保存并生效 |
| 管理后台 | 超限判断使用当日【工作日+限额时段】Token 使用量（>= 限额即拒绝） |
| 管理后台 | 超限时返回超限提示，降级服务不触发 |
| 个人看板 | "今日对话次数"已替换为"当日 Token 数"，与后端统计一致 |
| 个人看板 | 数值以 K / M 缩写展示，进度条显示百分比 |
| 个人看板 | 非限额时段（含周末、12:00–13:00、18:00 后）展示 Tooltip 说明 |
| Token 归属 | 跨边界请求（如 17:59 发起）按发起时间归属，计入当日限额 |
| 邮件通知 | 告警按原策略阈值触发，判断与文案均为 Token 口径 |
| 月度配额 | 月度 Token 配额逻辑、进度条颜色文案不受影响 |
| 数据迁移 | 旧字段标记 deprecated 且历史数据保留；新字段初始值 = floor(monthly_token_limit / 20 × 5) |
| 回归 | 其他页面与核心链路无异常 |

## 附：数据迁移说明

- **迁移策略**：直接替换字段，旧"日对话上限（次数）"字段废弃并标记 `deprecated`
- **历史数据**：旧字段数据、历史告警记录、审计日志**保留不删除**，标记为 `deprecated`
- **新字段初始值换算**：`daily_token_limit = floor(monthly_token_limit / 20 × 5)`（20 为固定常数，不按实际工作日动态变化）
- **quota_type**：日度配额采用 `daily_work_tokens`；`daily_chats` 标记废弃，迁移期仅允许映射到 `daily_work_tokens`，不得继续展示为"日对话轮次"
