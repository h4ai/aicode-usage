# 配额口径从"日对话上限"迁移为"当日 Token 限额"

## 0. 与现有需求文档对齐说明

本文档为**变更补充**，用于对齐并替换以下文档中与"每日请求次数 / 日请求上限 / 今日请求次数 / 日对话轮次（daily_chats）"相关的口径：

- `docs/requirements.md`（v0.7）
  - 影响章节：**四、配额体系**、**六、个人看板**、**七、管理员视图**。
  - 将其中的"每日请求次数"指标，替换为本文档定义的"当日Token（限额时段）"。

- `docs/requirements-quota-email-v2.md`（v0.3）
  - 将其中的日度配额项由历史的"日对话轮次（daily_chats）"迁移为"当日Token（限额时段）"。
  - quota_type 建议使用 `daily_work_tokens`（该文档已按此对齐）。

> 注：月度 Token 配额口径维持 `docs/requirements.md` 的定义，不在本文档变更范围内。

## 1. 背景

当前系统在「管理员后台 → 配额级别」使用"日对话上限（按对话/请求次数）"作为日配额口径；「个人看板」展示"今日对话次数"；邮件通知也基于该"次数口径"进行告警。

由于成本与资源消耗更贴近 Token 使用量，需要将上述能力整体迁移到 Token 口径。

## 2. 目标

1. 管理员后台「配额级别」：将"日对话上限"替换为"当日 Token 限额"。
2. 当日消耗取数口径：以【工作日 + 限额时段】内的 Token 使用量作为当日消耗（即：当日Token（限额时段））。
3. 个人看板：将"今日对话次数"调整为"当日 Token 数"，且口径与配额一致。
4. 邮件通知：沿用现有阈值/去重策略，仅将口径切换为 Token 限额与 Token 消耗。

## 3. 统计口径与规则（已确认）

### 3.1 作用范围

- 按 **用户（user）** 维度进行统计与限额。

### 3.2 时区

- 固定使用 **Asia/Shanghai**。

### 3.3 工作日

- **周一到周五**。
- 暂 **不考虑法定节假日**。

### 3.4 限额时段（多时段，原"工作时段"）

- 09:00–12:00
- 13:00–18:00

### 3.5 Token 归属时间判定

- **按请求发起时间**判定归属时段。即：请求在限额时段内发起，无论响应何时返回，该请求产生的全部 Token 均计入当日限额时段消耗。
- 跨时段边界的请求（如 17:59 发起、18:03 返回）：按发起时间归属，计入限额时段。

### 3.6 统计范围过滤

- **仅统计** 落在【工作日 + 限额时段】内的 Token（按请求发起时间判定）。
- **周末与非限额时段**产生的 Token：**完全不计入**
  - 当日消耗（配额判断）
  - 个人看板"当日 Token 数"
  - 邮件告警判断

### 3.6 Token 计算方式

- **沿用现有 Token 报表/查询口径**（与系统现有 Token 用量统计保持一致），并与 `docs/requirements.md` 的字段映射保持一致：
  - 输入 Token：ClickHouse `inputToken`
  - 输出 Token：ClickHouse `outputToken`
  - 总 Token：ClickHouse `totalToken`
- 当日 Token 消耗：默认使用 `totalToken` 聚合（若现有报表使用其他公式，以代码实现为准并保持一致）。

## 4. 功能需求

### 4.1 管理员后台 → 配额级别

#### 4.1.1 展示与文案

- 列表/详情/编辑页中：
  - "日对话上限" → "当日 Token 限额"。
  - 明确单位为 Token。

#### 4.1.2 配额配置

- 支持配置整数 Token 限额（需要覆盖较大数值）。
- 校验/权限策略沿用现有配额级别编辑逻辑。

#### 4.1.3 超限判断

- 将原本以"当日对话次数/请求次数"为消耗值的逻辑替换为：
  - 消耗值 = 当日【工作日 + 限额时段】Token 使用量
  - 超限条件：消耗值 >= 当日 Token 限额
- **超限后的系统行为**：与原"次数超限"行为一致（拒绝请求并返回超限提示）。降级服务为远期规划，本期不实现。

#### 4.1.4 API 字段

- 推荐将相关字段语义与命名同步切换为 Token（例如 `daily_token_limit`），避免旧字段名语义漂移。

### 4.2 个人看板 → 今日指标

- 将"今日对话次数"替换为"当日 Token 数"。
- 取数逻辑替换为：当日【工作日 + 限额时段】Token 总和（口径与配额一致）。
- **数值展示格式**：使用缩写形式（`120K`、`1.2M`），进度条显示百分比。
- **非限额时段 Tooltip**：当用户在非限额时段（周末 / 18:00 后）查看时，展示 Tooltip 说明"当前为非限额时段，此时段使用不计入当日配额"。

### 4.3 邮件通知（按 Token 限额）

#### 4.3.1 触发条件

- 触发依据从"次数口径"切换为：
  - 当日【工作日 + 限额时段】Token 使用量 / 当日 Token 限额
- 阈值档位、去重策略、发送时机：**沿用 `docs/requirements-quota-email-v2.md` 的策略**，仅替换统计口径为 Token。

#### 4.3.2 quota_type 对齐（已对齐）

日度配额项 quota_type 采用：

- `daily_work_tokens`：表示"工作日+限额时段"的当日 Token

对应文案：

- `quota_type_label = 当日Token（限额时段）`

兼容性说明：

- `daily_chats` 视为历史口径（对话轮次/事件数）并标记为废弃，不再用于新的告警与展示。
- 如代码侧需要兼容旧枚举值，仅允许在迁移期映射到 `daily_work_tokens`（不得继续展示为"日对话轮次"）。

#### 4.3.3 通知内容（建议）

邮件内容应包含（字段名可沿用模板占位符结构）：

- 当日已用 Token（工作日+限额时段口径）
- 当日 Token 限额
- 使用占比
- reset_time：次日 00:00（Asia/Shanghai）重置（与现有"自然日"概念对齐，但统计仅覆盖限额时段）

> 说明：虽然统计仅覆盖限额时段，但周期仍按自然日划分（用于 period_key 去重与展示）。

#### 4.3.4 阈值默认值对齐

- 若系统已实现 v2 文档的 `notification.thresholds: [50, 80, 100]`，则当日 Token 同样适用。
- 若仍停留在旧版仅 80% 的实现，则当日 Token 也按同一策略触发（保持一致）。

### 4.4 UI 指标命名对齐（与 requirements.md）

- `docs/requirements.md` 中的以下字段/文案需要在实施时统一替换为 Token 口径：
  - "每日请求次数进度条" → "当日 Token 进度条（限额时段）"
  - "今日请求次数" → "当日 Token"
  - "日请求上限" → "当日 Token 限额"
  - "日对话轮次" → "当日Token（限额时段）"

> 该节仅定义对齐要求；具体页面与接口字段以实现时的代码定位为准。

### 4.5 保持不变的部分（明确范围）

- 月度 Token 配额、月度进度条颜色与文案：沿用 `docs/requirements.md`（不变）。
- 邮件通知的"月度 Token"告警策略：沿用现有（不变）。

## 5. 数据迁移需求（已确认）

### 5.1 迁移策略

- 采用 **直接替换字段**：旧"日对话上限(次数)"字段被新的"当日 Token 限额"字段替换，旧字段废弃。
- **历史数据保留**：旧字段数据及已触发的历史告警记录、审计日志保留不删除，标记为 `deprecated`。

### 5.2 新字段初始值（从月度限额换算）

- 新"当日 Token 限额"初始值：
  - `daily_token_limit = floor(monthly_token_limit / 20 * 5)`
  - 取整规则：**向下取整（floor）**

> 注：20 为固定常数（按确认规则实现），不按自然月实际工作日动态变化。

## 6. 影响面（排查清单）

1. 配额与限流：所有基于"次数"的日限流/拒绝逻辑需要切换为 Token。
2. 统计与榜单：若存在"今日对话次数/请求数"卡片、榜单或导出字段，需要替换或新增 Token 指标。
3. 图表与趋势：涉及"今日"指标的趋势图可能需要同步替换口径与文案。
4. 缓存与预聚合：若有按天缓存/预聚合表，需要补齐 Token 维度。
5. API 契约：字段改名会影响前端与外部调用方，需要同步。
6. 权限与审计：配额修改审计日志/操作记录字段可能需要同步。
7. 测试与 QA 用例：单测、E2E、UI 截图测试中的断言与文案受影响。
8. 邮件模板：主题/正文/占位符字段、阈值配置项需要同步。
9. 数据脚本：生成/导入测试数据脚本可能需要同步 token 字段。

## 7. 验收标准

- 管理后台：
  - 配额级别页面已显示"当日 Token 限额"，可保存并生效。
  - 超限判断使用当日【工作日+限额时段】Token 使用量。
- 个人看板：
  - "今日对话次数"已替换为"当日 Token 数"，且与后端统计一致。
- 邮件通知：
  - 告警仍按原策略触发，但判断与文案展示均为 Token 口径。
- 回归：
  - 不影响其他页面与核心链路。
