# Web UI：管理后台与统计功能

## 1. 需求背景
- 目标：提供一个全局的系统管理和数据看板界面，帮助管理员监控系统健康度和资产使用情况。
- 成功标准：管理员能够在一个页面看到宏观的活跃用户数、下载排名，并且能管理系统中用户的角色和权限。
- 范围边界：仅包括全局统计看板（Admin Dashboard）和基础的用户列表/角色管理，不包含底层日志导出。

## 2. 需求描述
- 功能概述：构建系统的 `/admin` 路由（仅管理员可见），左侧包含菜单栏（Dashboard、用户管理、审计日志等）。核心提供数据可视化的图表，如热门 Top 10 的插件、最近 30 天的总下载趋势。并在用户管理页面支持管理员调整用户的角色（例如提拔某人为 PUBLISHER 或 REVIEWER）。
- 业务价值：为运维和管理人员提供宏观视角，识别出哪些插件最有价值（可进行推广），哪些人活跃，以及处理极个别情况下的权限调整。
- 核心场景：月底，系统管理员登录进入后台，看到仪表盘显示本月新增下载量 3000 次，其中 `@data-team/data-analyzer` 插件高居榜首。接着，管理员接到需求，在"用户管理"页搜索某新入职员工，将其从 USER 提升为 PUBLISHER，使其能够发布公司级插件。

## 3. 用户旅程
- 主要用户：系统管理员（Admin）
- 主路径（看数据）：
  1. 管理员登录后点击右上角的"管理后台"
  2. 页面默认显示 Dashboard
  3. 看到总活跃用户、总下载量、本周热门 Top 10 的数据图表
  4. 可以切换时间范围（最近7天、30天、全部）
- 主路径（管用户）：
  1. 点击左侧菜单的"用户管理"
  2. 搜索指定用户的域账号或姓名
  3. 在列表中点击该用户的"编辑角色"
  4. 在弹出的下拉框中选择新角色（如：REVIEWER）
  5. 确认修改，页面提示成功
- 主路径：
  1. 待补充
- 异常路径：
  1. 普通用户（非 Admin）尝试访问 `/admin` 及其子页面 → 被 TanStack Router 的路由守卫拦截，重定向回首页并提示"无权限访问"
  2. 后端接口超时或报错 → Dashboard 图表区显示错误骨架屏，提示"获取统计数据失败"

## 4. 页面结构
- 页面布局：经典的带侧边栏（Sidebar）的管理后台布局。顶部为包含面包屑的 Header，主体为图表或列表。
- 关键区域：
  - 侧边栏：Dashboard, 用户管理, (预留: 审计日志)
  - 概览区：顶部四个核心指标卡片（总用户、总 Skill、总模板、本周下载量）
  - 图表区：下载趋势折线图，热门排名条形图 / Top 10 列表
  - 用户管理列表：表格形式展示所有同步过来的 AD 用户信息（头像、姓名、部门、邮箱、角色），带搜索框和分页
  - 角色修改弹窗：单选或下拉选择角色，保存按钮
- 状态流转：菜单切换 → 加载数据(Skeleton) → 渲染图表/表格 → 修改权限(Loading) → 刷新列表

## 5. 输入输出

### 5.1 输入
| 场景 | 输入 | 说明 |
|------|------|------|
| 筛选数据 | 选择日期/下拉 | 选择最近 N 天查看趋势图 |
| 搜索用户 | 文本 | 在用户列表中检索姓名或账号 |
| 修改角色 | 下拉选择 | 在用户行点击编辑后改变其权限级别 |
| 保存权限 | 点击提交 | 触发后端的 PATCH 操作 |

### 5.2 输出
| 场景 | 输出 | 说明 |
|------|------|------|
| 统计报表 | 图表/卡片 | 调用 `/api/v1/admin/dashboard` 后渲染的 ECharts/Recharts 视图 |
| 用户列表 | 分页表格 | 列出同步的 AD 用户详情，并展示其当前系统角色 |
| 操作反馈 | Toast | 角色修改成功或失败（如降级自己时后端报错）的全局提示 |
| 越权拦截 | 重定向 | 普通用户访问 `/admin` 将自动跳回首页 |
