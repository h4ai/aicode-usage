# 项目模板管理功能

## 1. 需求背景
- 目标：提供项目初始化模板（Template）的管理能力，支持通过命名空间隔离不同团队的模板。
- 成功标准：用户能在其所属命名空间下创建、查看、更新模板及其版本，配置 Skill 依赖。
- 范围边界：仅包括模板的元数据管理、命名空间管理、Git源配置及依赖版本声明。不含 CLI 本地执行逻辑及独立页面展示。

## 2. 需求描述
- 功能概述：允许发布者以团队（命名空间）为维度管理模板资产。每个模板可以声明依赖的 Skill 及版本范围。系统自动跟踪 Skill 更新情况，符合语义化版本的则自动同步。
- 业务价值：为 CLI 提供服务端数据支撑，将散落的项目骨架集中管理，提升架构一致性。
- 核心场景：架构组成员在 `@backend-team` 命名空间下创建一个名为 `java-springboot` 的模板，并配置了通过公司 GitLab 仓库自动拉取更新。

## 3. 用户旅程
- 主要用户：模板发布者（Publisher）、管理员（Admin）
- 主路径：
  1. 发布者申请或直接创建一个命名空间（如 `@frontend-infra`）
  2. 在该命名空间下新建一个 Template 条目
  3. 通过 Web 页面或 CLI 上传新版本（ZIP 或指定 Git 地址）
  4. 系统解析清单，提取包含的 Skill 依赖（如 `code-review: ^1.2.0`）
  5. 新版本进入审核流，审核通过后变为可下载状态
- 异常路径：
  1. 尝试在无权限的命名空间下发布模板 → 提示 403 权限不足
  2. 指定的 Git 凭证无效或无法拉取仓库 → 提示来源验证失败
  3. 模板依赖的 Skill 版本在市场中不存在 → 上传校验失败，提示修正版本号

## 4. 页面结构
- 页面布局：命名空间管理页 + 模板发布表单
- 关键区域：
  - 命名空间成员管理区（添加/移除成员，分配 ADMIN/MEMBER 角色）
  - Git 凭证管理区（配置 Token 或 SSH Key）
  - 依赖关系视图（查看当前模板版本解析出的具体 Skill 列表及版本）
- 状态流转：创建命名空间 → 创建模板 → 发布版本 → 自动/手动同步依赖 → 更新版本

## 5. 输入输出

### 5.1 输入
| 场景 | 输入 | 说明 |
|------|------|------|
| 创建命名空间 | 名称字符串 | 类似 npm 的 scope，如 `@team-name` |
| 配置 Git 凭证 | Token/Key | 用于拉取内部私有代码库的代码 |
| 声明依赖 | JSON 格式 | `template.json` 中的 skills 字段 |

### 5.2 输出
| 场景 | 输出 | 说明 |
|------|------|------|
| 版本上传 | 解析结果 | 成功解析出配置文件并展示需要注入的变量 |
| 依赖更新 | 站内通知 | 依赖的 Skill 发布 Major 版本时，通知模板作者 |
| 安全存储 | 密文数据 | 所有凭证信息后端加密存储，不返回明文 |
