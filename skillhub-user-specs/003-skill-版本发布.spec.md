# Skill 版本发布功能

## 1. 需求背景
- 目标：支持用户为创建的 Skill 发布新版本，支持上传 ZIP 包或通过 Git 仓库关联发布。
- 成功标准：用户能够成功上传符合 SemVer 规范的 Skill 包，系统能解析配置清单，并支持通过 Git 同步。
- 范围边界：包括 ZIP 上传、解压解析、Git 来源选择、防重复发布和归档操作。

## 2. 需求描述
- 功能概述：发布者在已有 Skill 下，通过上传包含 SKILL.md 及其依赖的 ZIP 包，或填写 Git 仓库地址及分支/标签，创建新的 SemVer 版本。版本提交后进入草稿或待审核状态。
- 业务价值：实现能力的迭代演进和安全管控，确保发布包的完整性和可追溯性。
- 核心场景：开发者完成 Skill 改进，打成 ZIP 包上传系统并标记为 v1.1.0；或指定 Git 仓库的 tag v1.1.0 进行发布。

## 3. 用户旅程
- 主要用户：发布者（Publisher）。
- 主路径（ZIP 上传）：
  1. 发布者进入 Skill 详情页，点击"发布新版本"
  2. 选择"本地上传 (ZIP)"方式
  3. 拖拽或选择本地的 ZIP 文件（包含 SKILL.md）
  4. 填写遵循 SemVer 规范的版本号（如 1.0.0）
  5. 提交上传，系统进行文件大小和类型校验
  6. 解析包内 manifest，生成版本记录
- 主路径（Git 发布）：
  1. 选择"Git 仓库"方式
  2. 选择或新建 Git 凭证
  3. 输入仓库 URL、分支/标签/Commit Hash 和子目录（可选）
  4. 填写版本号
  5. 提交发布，系统异步拉取解析
- 主路径：
  1. 待补充
- 异常路径：
  1. 版本号格式错误（非 SemVer） → 提示格式错误
  2. 版本号已存在冲突 → 提示版本已发布，需更新版本号
  3. ZIP 包超过 200MB 或包含恶意文件 → 提示大小超限或格式不合法
  4. ZIP 内部无 SKILL.md → 提示缺少核心清单文件
  5. 审核未通过 → 下载受限，需联系管理员

## 4. 页面结构
- 页面布局：弹窗或全屏表单
- 关键区域：
  - 发布方式切换 Tab（本地 ZIP / Git 仓库）
  - 版本号输入框
  - 本地上传区（拖拽上传组件）
  - Git 配置区（凭证选择、URL 输入框、Ref 输入框）
  - 进度条/提示区
- 状态流转：草稿 (DRAFT) → 待审核 (PENDING_REVIEW) → 已发布 (PUBLISHED) 或 驳回 (REJECTED)

## 5. 输入输出

### 5.1 输入
| 场景 | 输入 | 说明 |
|------|------|------|
| 填写版本号 | SemVer字符串 | 如 1.0.0，必填且不能重复 |
| 上传文件 | ZIP/TAR.GZ | 限制 200MB 以内的压缩包 |
| 选择Git来源 | 凭证、URL、Ref | 凭证需提前配置或当场新建 |
| 提交发布 | 点击事件 | 触发解析和上传流程 |

### 5.2 输出
| 场景 | 输出 | 说明 |
|------|------|------|
| 解析成功 | 版本记录 | 生成待审核的版本条目，解析出的清单属性 |
| 解析失败 | 错误提示 | 提示找不到 manifest 或超过解压限制 |
| 发布冲突 | 冲突提示 | 当前版本已存在 |
| 状态变更 | 页面刷新 | 跳转到该版本的审核状态页 |
