# Web UI：审核大盘与管理

## 1. 需求背景
- 目标：为安全审核人员和系统管理员提供专属的工作台，高效处理积压的 Skill/模板发布申请。
- 成功标准：审核员能够在一个页面查看到所有待办任务，清晰了解自动扫描的风险项，并进行快速审批或打回。
- 范围边界：仅包括审核大厅列表页和单个审核工单的详情决策页面（ScanReportView + DecisionPanel）。

## 2. 需求描述
- 功能概述：构建管理员专属的 "/review" 路由，左侧或上方展示待办（PENDING_MANUAL）及审核历史的列表。点击工单后，右侧展示此版本的自动安全合规扫描结果（绿/黄灯），以及包含"批准/要求修改/驳回"的决策面板。
- 业务价值：极大提高人工审核的吞吐量，将晦涩的后端扫描日志转化为直观的 UI 卡片，降低漏判风险。
- 核心场景：安全部门的员工登录后进入审核大盘，看到昨天新提交的 5 个待办。点击第一个进入，看到 ScanReport 亮了一个黄灯（包含外部 HTTP 请求），他查看代码没发现敏感数据外泄，于是填写"域名白名单已确认"的评价，打出 4 分质量分，点击"Approve"，工单状态变更为已通过。

## 3. 用户旅程
- 主要用户：审核员（Reviewer）、管理员（Admin）
- 主路径：
  1. 审核员登录并点击导航栏的"审核大厅"
  2. 页面显示 PENDING_MANUAL 状态的任务列表，展示申请人、发布时间、版本号
  3. 审核员点击一条待办任务，进入审核详情页
  4. 页面左侧/上方展示 `ScanReportView`，列出各项自动扫描结果（如：无恶意文件-绿，发现可疑网络请求-黄）
  5. 审核员可选择查看代码/配置 Diff（`CodeDiffViewer`）
  6. 在右侧 `DecisionPanel` 中，审核员必须选择质量评分（1-5星）
  7. 审核员选择"Approve"并填写可选评价，点击提交
  8. 页面弹出成功 Toast，该任务从列表中移除
- 异常路径：
  1. 发现严重违规 → 审核员必填"Comment"说明原因，点击"Reject"
  2. 需要作者微调 → 必填"Comment"，点击"Revision Requested"
  3. 自己提交的插件 → 系统拦截，不在待办列表中显示，详情页操作按钮置灰并提示"不能审核自己的提交"

## 4. 页面结构
- 页面布局：典型的左右分栏管理后台布局。左侧工单列表，右侧大区域展示详情与决策面板。
- 关键区域：
  - 左侧任务列表：带状态过滤 Tab (待审核/已审核)，卡片包含标题、版本、作者、提交时间
  - 右侧详情区顶部：`ScanReportView` (用红黄绿盾牌/Check标示各项自动扫描指标)
  - 详情中间区：版本更新日志 (Changelog)、代码变动预览 (`CodeDiffViewer`)
  - 右侧/悬浮面板：`DecisionPanel`（三个大按钮: Approve(绿)/Revision(黄)/Reject(红)；质量评分组件；必填/选填的文本评价框）
- 状态流转：列表加载 → 选中详情 → 查看报告 → 填写意见并提交(Loading) → 刷新列表

## 5. 输入输出

### 5.1 输入
| 场景 | 输入 | 说明 |
|------|------|------|
| 选择工单 | 点击列表 | 切换右侧显示的审核详情 |
| 填写评分 | 点击星级组件 | 1-5分评估质量 |
| 填写意见 | 文本输入 | 驳回或要求修改时必须填写的原因 |
| 决策提交 | 按钮点击 | 触发 Approve/Reject 等操作 |

### 5.2 输出
| 场景 | 输出 | 说明 |
|------|------|------|
| 扫描报告 | 可视化组件 | 将后端的 JSON `autoScanDetail` 转化为红黄绿直观卡片 |
| 代码差异 | Diff视图 | 高亮显示新增、删除和修改的行（可选进阶功能） |
| 操作结果 | 列表更新与 Toast | 成功后通知用户并在前端移除该待办项 |
