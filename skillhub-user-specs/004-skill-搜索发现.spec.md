# Skill 搜索与发现功能

## 1. 需求背景
- 目标：提供精准的自然语言语义搜索功能，帮助用户快速找到所需的 Skill 资产。
- 成功标准：用户输入自然语言描述能够召回相关 Skill；在 AI 搜索服务不可用时，系统能自动降级为关键词搜索而不报错。
- 范围边界：包括全局搜索栏、语义匹配结果展示、权限隔离过滤以及服务降级处理。

## 2. 需求描述
- 功能概述：系统集成大模型向量表示（Embedding），支持用户通过描述业务需求或意图（如"帮我分析财务报表"）而非精确关键词来搜索 Skill。搜索结果根据语义相似度和下载热度综合排序。
- 业务价值：极大降低用户的查找成本，提升系统易用性；通过自然语言理解发掘潜在有用的内部工具。
- 核心场景：用户不记得具体插件名称，只知道需要"处理表格数据"的工具，通过搜索框输入自然语言即可找到相关的 Data Analyzer 插件。

## 3. 用户旅程
- 主要用户：所有企业员工
- 主路径：
  1. 用户在顶部全局搜索框（OmniSearchBar）输入查询需求
  2. 系统延迟 300ms 后自动触发搜索请求
  3. 系统将查询语句转为向量，并在数据库中比对相似度
  4. 系统根据用户部门权限，自动过滤掉无权访问的私有/他部门 Skill
  5. 下拉列表或搜索结果页展示最相关的 Skill（最多 50 条）
  6. 结果卡片展示匹配度（如"85% 匹配"）
- 异常路径：
  1. AI 向量搜索服务不可用 → 系统瞬间无缝降级为传统关键词模糊搜索，不展示匹配度百分比
  2. 搜索结果为空 → 提示"未找到相关 Skill，尝试换个词描述？"

## 4. 页面结构
- 页面布局：顶部全局悬浮搜索栏 + 独立搜索结果页
- 关键区域：
  - 搜索输入框（支持快捷键聚焦）
  - 实时联想下拉面板（最多展示前 5-10 条高相关结果）
  - 分类及部门过滤面板（可选，在搜索结果页左侧）
  - 结果列表区（卡片形式，包含名称、简介、标签、匹配度标识）
- 状态流转：输入中 → 搜索加载中 → 展示结果 / 展示空状态

## 5. 输入输出

### 5.1 输入
| 场景 | 输入 | 说明 |
|------|------|------|
| 关键词输入 | 自然语言文本 | 用户描述意图或功能关键词 |
| 筛选条件 | 点击勾选 | 在结果页勾选特定分类或部门（可选） |

### 5.2 输出
| 场景 | 输出 | 说明 |
|------|------|------|
| 搜索成功 | Skill 列表 | 按相似度和热度综合排序，最多 50 条 |
| 匹配度标识 | 百分比数字 | 例如 85% 匹配，辅助用户判断相关性 |
| 服务降级 | 关键词结果 | 向量服务不可用时，降级为文本检索，不显示匹配度 |
| 无权限结果 | 自动过滤 | 系统底层拦截，用户绝不会搜出无权查看的 Skill |
