# Web UI：版本上传功能

## 1. 需求背景
- 目标：提供一个直观的前端交互界面，支持发布者上传 Skill 或模板的打包文件并完成版本发布。
- 成功标准：用户能够顺畅地拖拽文件上传、填写版本号并清晰看到进度及校验反馈。
- 范围边界：仅包含文件上传页面的交互，如表单输入、拖拽组件、进度条及错误提示，不包含审核流转。

## 2. 需求描述
- 功能概述：在系统的"我的发布"或对应资产详情页中，提供"发布新版本"入口。弹出专门的上传组件（VersionUploader），支持本地 ZIP/TAR.GZ 文件拖拽上传或 Git 仓库信息填写。
- 业务价值：降低开发者发布新版本的操作门槛，通过友好的即时校验（如文件格式、版本号冲突）避免无效的后台请求。
- 核心场景：开发者在本地打包好 `my-skill-v1.1.0.zip`，登录系统进入自己开发的插件详情页，点击发布新版，将文件拖入虚线框，填写 `1.1.0` 后点击提交，等待进度条走满跳转到审核状态。

## 3. 用户旅程
- 主要用户：发布者（Publisher）及以上权限者
- 主路径（ZIP）：
  1. 发布者点击"发布新版本"按钮
  2. 页面弹出全屏表单或进入专门的 `/skills/slug/upload` 页面
  3. 鼠标将 ZIP 文件拖入带有虚线的拖放区
  4. 页面识别出文件名，显示文件大小
  5. 填写版本号输入框（例如：1.1.0）
  6. 点击"提交"按钮
  7. 页面展示上传进度条（0% → 100%）
  8. 提交成功，跳转回详情页，显示当前版本处于"自动扫描中"（PENDING_AUTO）状态
- 主路径：
  1. 待补充
- 异常路径：
  1. 拖入的文件非 ZIP/TAR.GZ 或大小超过 200MB → 页面变红，提示"文件类型错误或超大"
  2. 版本号格式错误或未填 → 提交按钮置灰，输入框下方标红报错
  3. 后端解析失败（如未找到 SKILL.md） → 上传中断，弹出全局 Toast 错误提示

## 4. 页面结构
- 页面布局：居中对齐的卡片式表单布局
- 关键区域：
  - 顶部返回按钮与页面标题
  - 方式切换 Tab：本地上传 / Git 仓库拉取
  - 版本号输入区（带 SemVer 格式校验提示）
  - 本地上传区（VersionUploader）：大虚线框，支持点击选择文件和拖拽，内部带上传图标
  - Git 配置区（若切换至 Git）：凭证下拉框、仓库 URL、分支/Tag 输入框
  - 底部操作栏：取消按钮 / 提交按钮（带 Loading 状态）
- 状态流转：空闲状态 → 文件拖入(高亮) → 校验文件 → 填写表单 → 提交上传中(进度条) → 成功跳转/报错恢复

## 5. 输入输出

### 5.1 输入
| 场景 | 输入 | 说明 |
|------|------|------|
| 切换上传方式 | 鼠标点击 | Tab 切换本地或 Git |
| 文件选择 | 文件拖拽/点击 | ZIP 或 TAR.GZ 格式文件 |
| 填写版本 | 文本输入 | 遵循 SemVer 规范的版本号字符串 |
| 填写 Git 信息 | 文本+下拉 | 选择已存凭证及填写仓库信息 |
| 提交表单 | 点击提交 | 触发上传与后端解析接口 |

### 5.2 输出
| 场景 | 输出 | 说明 |
|------|------|------|
| 文件校验 | 界面反馈 | 文件大小或格式不合规时立即在前端标红提示 |
| 上传进度 | 进度条组件 | 实时展示上传百分比及正在解析状态 |
| 上传结果 | 跳转或 Toast | 成功后跳转审核页；失败后 Toast 提示并保留已填信息 |
