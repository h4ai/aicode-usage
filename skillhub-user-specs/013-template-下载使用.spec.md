# 模板下载使用

## 1. 需求背景
- 目标：提供给开发者一种快速获取已打包或指定模板的途径，支持跨不同工具栈的灵活拉取。
- 成功标准：开发者能够通过 Web 下载按钮获取模板 ZIP，或通过 CLI `init` 命令完整拉取并根据特定 AI 工具（如 `--ai claude`）注入相应的隐藏配置目录。
- 范围边界：包含对当前版本下载和脚手架依赖的解包，涵盖 CLI 初始化逻辑及对应下载日志与排行榜更新；但具体的代码逻辑修改由拉取后的用户在本地执行。

## 2. 需求描述
- 功能概述：模板的分发与获取机制，允许用户在本地通过 CLI 一键注入完整的开发环境配置，并在 Web 端查看热度与排行。
- 业务价值：极大程度减少“Hello World”配置阶段，直接应用架构师的最佳实践，避免低级搭建错误。
- 核心场景：新入职员工或新项目启动时，使用 `skillhub init --template @team/name` 拉取脚手架并根据参数生成相应的如 `.claude/` 目录。系统会记录并计算本周最热的模板。

## 3. 用户旅程
- 主要用户：一线开发人员、项目新成员
- 主路径：
  1. 用户在终端执行 `skillhub init --template @backend-team/java-springboot --ai cursor`。
  2. CLI 提示输入 `projectName` 等模板变量。
  3. CLI 请求 SkillHub 远端获取该模板的 manifest 和最新的依赖。
  4. 远端返回脚手架 ZIP 下载链接及所有关联的 Skill 确切版本。
  5. CLI 下载脚手架文件、执行变量替换、展开至本地目录（生成 `.cursor/rules/`）。
  6. 远端记录一次有效的下载（防刷机制校验通过）。
  7. CLI 在本地生成 `.skillhub/template.lock` 并可能执行后置钩子（如 `npm install`）。
- 异常路径：
  1. 未找到目标模板或无权访问 → CLI 或 Web 报错“未找到该模板，可能处于草稿/已下架或无访问权限”。
  2. 用户输入参数校验失败 → 提示“projectName 不能包含特殊字符”或“必填项不能为空”。
  3. 重复请求刷榜（短时间重复下载） → 计入一次有效下载，后续调用虽下载成功但在统计面板中 `downloadCount` 不递增。
  4. 下载时网络超时 → CLI 提示“连接 SkillHub 超时，请重试或检查网络”。

## 4. 页面结构
- 页面布局：模板详情页右侧或顶部的核心操作区，并带有单独的热门排行榜侧边栏。
- 关键区域：
  - 核心操作区：包含一键复制的 CLI 命令代码块及独立的“直接下载 ZIP”按钮。
  - 数据面板：展现总下载量、周度活跃使用、下载趋势图（近 30 天）。
  - 排行榜模块：在“发现模板”页面的侧边，列出 `Top 10` 模板。
- 状态流转：未获取 -> 请求中/解析变量中 -> 下载解压中 -> 本地初始化完成

## 5. 输入输出

### 5.1 输入
| 场景 | 输入 | 说明 |
|------|------|------|
| 获取模板命令 | 模板标识及 AI 工具 | 例如 `@backend-team/java-springboot --ai claude` |
| 模板变量补充 | CLI 交互式输入 | 例如输入项目名称、端口号、包名等必填变量 |
| 页面点击下载 | 按钮点击操作 | 用户选择通过 Web 页面直接获取压缩包实体 |

### 5.2 输出
| 场景 | 输出 | 说明 |
|------|------|------|
| 脚手架解包 | 本地目录生成 | 生成基础代码、依赖描述文件及特定的 `.ai/` 目录结构 |
| 后置执行 | 终端日志提示 | `npm install` 或是 `mvn clean` 的执行成功日志 |
| 下载统计 | 统计看板数值变化 | 周排行和总下载计数更新，管理员可见明细及排重后的活跃度 |
