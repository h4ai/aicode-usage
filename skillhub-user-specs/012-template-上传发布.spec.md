# 模板上传发布

## 1. 需求背景
- 目标：支持开发者将带有脚手架代码和配置（AI 专属工具规则等）的项目模板通过 Web 或 CLI 上传到 SkillHub 中。
- 成功标准：用户可以通过 Web 界面成功上传 ZIP 压缩包或绑定 Git 仓库提交模板，CLI `publish` 功能同样稳定可用；发布后能够成功触发审核流程。
- 范围边界：支持 ZIP 上传和基于 Git URL、Tag/Branch、Subpath 的拉取；不包含在线直接修改代码文件，仅作上传分发。

## 2. 需求描述
- 功能概述：提供“项目初始化模板”的上传发布入口。模板归属于类似 npm 的命名空间（Namespace），且拥有特定的版本管理。
- 业务价值：实现研发脚手架的统一管理分发，降低新项目的启动成本，沉淀团队优秀的 AI 工程实践（如 .claude, .cursor 配置）。
- 核心场景：架构师或高阶开发者打磨好一套含 AI rules 的项目骨架，通过打包 ZIP 或挂载 Git 仓库的方式，在对应团队的 Namespace 下发布为一个新 Template 或其新版本。

## 3. 用户旅程
- 主要用户：内部研发人员、架构师、团队负责人（需有对应 Namespace 的权限）
- 主路径：
  1. 用户在 Web 端进入“发布模板”页面（或在本地终端准备执行 `skillhub template publish`）。
  2. 选择目标 Namespace（如 `@backend-team`）并填写模板名称（如 `java-springboot`）。
  3. 提供模板来源：上传本地 ZIP 文件，或输入 Git 仓库 URL 及指定的分支/Tag/子目录，或者直接由 CLI 从当前目录打包。
  4. 系统解析 `manifest` (如 `template.json`)，自动读取版本号（SemVer）、依赖 Skill 列表及描述信息。
  5. 检查是否符合大小限制，校验依赖的 Skill 是否在系统中存在。
  6. 点击“提交发布”按钮。
  7. 模板进入 `PENDING_REVIEW` 状态，等待审核。
- 异常路径：
  1. Namespace 权限不足 → 提示“您无权在该命名空间下发布，请联系管理员”，中止发布。
  2. 文件大小超限（如大于 500MB） → 提示“上传包或仓库超出体积限制”，拒绝接收。
  3. Git 仓库无法访问 / 凭证无效 → 提示“Git 连通性测试失败，请检查仓库地址或凭证”，允许用户重试或更换凭证。
  4. 依赖 Skill 未找到 → 提示“清单中包含未知的 Skill 依赖”，要求修改 manifest 后重新上传。
  5. 版本号不符合 SemVer 规范或低于已有版本 → 提示“版本号必须符合语义化版本规范且大于历史版本”，拦截上传。

## 4. 页面结构
- 页面布局：居中表单或左右分栏（左侧操作区，右侧实时预览区）
- 关键区域：
  - 顶部步骤条：填写信息 -> 上传资源 -> 解析确认 -> 提交完成
  - 命名空间与基础信息区（Namespace 选择器、模板名称输入框）
  - 资源来源选择区（Tab 切换：本地 ZIP 上传 / Git 仓库关联）
  - 清单预览区（只读展示或轻量级 JSON 编辑器展示 `template.json`）
  - 发布操作栏（“提交发布”、“取消”）
- 状态流转：起草态 (Draft) -> 上传/拉取中 -> 解析校验中 -> 待审核 (Pending Review)

## 5. 输入输出

### 5.1 输入
| 场景 | 输入 | 说明 |
|------|------|------|
| 选择命名空间 | 命名空间下拉选 | 选择该模板归属的 Team/部门空间 |
| 提供模板文件 | ZIP 文件 / Git 参数 | 包含脚手架代码和 manifest 的文件来源 |
| 设置凭证 | Git 凭证选项 | 针对私有 Git 仓库，选择或新建拉取凭证 |
| 提交发布动作 | 按钮点击 | 确认无误，正式触发创建或更新操作 |

### 5.2 输出
| 场景 | 输出 | 说明 |
|------|------|------|
| 解析清单 | 清单预览内容 | 在界面展示解析到的版本号、描述、依赖项等 |
| 提交成功 | 成功提示及跳转 | 提示“已提交审核”，跳转至模板详情页或审核状态页 |
| 校验失败 | 错误警告信息 | 详细告知失败原因（包太大、依赖缺失、权限不足等） |
