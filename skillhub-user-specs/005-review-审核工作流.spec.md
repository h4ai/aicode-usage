# Skill 审核工作流功能

## 1. 需求背景
- 目标：确保发布到市场的 Skill 资产安全、合规、高质量。
- 成功标准：所有新发布的版本必须经过自动扫描和/或人工审核才能被普通用户下载；违规内容被自动拦截；审核过程可追溯。
- 范围边界：包括自动扫描规则配置、人工审核任务分配、审核决策操作及超时告警机制。

## 2. 需求描述
- 功能概述：发布者提交新版本后，系统首先进行自动化的安全和合规扫描。扫描通过后进入人工审核池，由系统自动分配给有权限的审核员。审核员检查后给出"批准"、"驳回"或"要求修改"的结论。
- 业务价值：防止恶意代码或不合规工具进入企业内网，保障企业信息安全；通过质量打分提升市场整体插件质量。
- 核心场景：员工开发了一个包含 Shell 脚本的插件并提交发布。系统自动扫描未发现高危命令，将其流转给安全部门的审核员。审核员查看代码 Diff 后点击"批准"，该版本正式对外可见。

## 3. 用户旅程
- 主要用户：发布者（Submitter）、审核员（Reviewer）、管理员（Admin）
- 主路径（审核员视角）：
  1. 审核员登录系统，进入"审核大盘"
  2. 查看分配给自己的待审核任务列表
  3. 点击进入详情，查看自动扫描报告（绿灯/黄灯）
  4. 查看该版本的变更说明及文件内容/Diff
  5. 在右侧操作面板填写审核意见和质量评分（1-5分）
  6. 点击"批准"，任务完成，Skill 版本转为发布状态
- 主路径：
  1. 待补充
- 异常路径：
  1. 自动扫描发现高危后门 → 系统直接拦截（自动驳回），不进入人工池
  2. 审核员认为有瑕疵但不致命 → 点击"要求修改"，打回给发布者
  3. 发现严重违规 → 点击"驳回"，版本直接作废
  4. 任务超时未审核 → 系统通过企业微信/飞书发送告警通知给审核组
  5. 尝试审核自己提交的 Skill → 提示"不能审核自己的提交"，按钮置灰

## 4. 页面结构
- 页面布局：后台管理风格，左侧列表，右侧详情
- 关键区域：
  - 待办列表区（支持按状态、分类筛选）
  - 扫描报告视图（可视化展示各项安全指标检测结果）
  - 代码/文件对照区（如果包含配置或文本文件）
  - 决策操作面板（包含评论框、评分组件和批准/驳回/要求修改三个主按钮）
  - 审核时间线展示区
- 状态流转：等待自动扫描 → 等待人工审核 → 审核中 → 已批准 / 已驳回 / 要求修改

## 5. 输入输出

### 5.1 输入
| 场景 | 输入 | 说明 |
|------|------|------|
| 认领任务 | 点击事件 | 审核员主动从公共池认领任务 |
| 填写意见 | 文本 | 驳回或要求修改时必填的原因说明 |
| 质量打分 | 1-5 星 | 对该版本质量的综合评价 |
| 提交决策 | 按钮点击 | 触发状态机流转 |

### 5.2 输出
| 场景 | 输出 | 说明 |
|------|------|------|
| 自动拦截 | 拦截通知 | 扫描出恶意文件直接终结流程，通知发布者 |
| 审核通过 | 状态发布 | 对外可见，更新最新发布版本号 |
| 要求修改 | 任务打回 | 状态变更，等待发布者重新提交新版本 |
| 超时告警 | 外部消息 | 超过3天未审，推送到工作群 |
