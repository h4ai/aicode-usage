# 模板版本更新

## 1. 需求背景
- 目标：提供给开发者一种快速、一致的途径更新已初始化项目的脚手架文件和 Skill 依赖，保持与远程最新最佳实践同步。
- 成功标准：用户能够通过 CLI `skillhub template update` 命令一键更新到符合 SemVer 的新版本，自动同步依赖版本，并在发生 major 变更或冲突时提供安全的机制。
- 范围边界：仅处理基于 `skillhub init` 产生的本地项目目录结构，包含依赖自动同步、冲突文件提示和 Major 版本通知；不处理未被管理的业务代码的重构。

## 2. 需求描述
- 功能概述：一个在本地已初始化项目中，检查并拉取最新模板及关联 Skill，自动合并或给出更新冲突文件的版本管理功能。
- 业务价值：消除项目中潜藏的低版本漏洞，让架构师的更新能平滑渗透到每个正在进行的业务线，同时让旧项目能够轻松获知重要更新（Outdated 检查）。
- 核心场景：架构师对 `@backend-team/java-springboot` 进行安全补丁更新，研发人员在本地执行 `update`，脚手架中的配置文件被更新，而其业务代码安全地被保留；遇到不兼容更新时，得到冲突提示。

## 3. 用户旅程
- 主要用户：一线开发人员、项目维护者
- 主路径：
  1. 用户在已初始化的项目终端执行 `skillhub template outdated` 检查是否有可用新版本。
  2. 若有，执行 `skillhub template update [--version <version>] [--dry-run]`。
  3. CLI 请求远端，对比本地 `.skillhub/template.lock` 与最新版本。
  4. 显示更新计划（如哪些文件会修改、哪些依赖会自动同步）。
  5. 确认更新后，下载最新的包：仅更新未被用户修改过的脚手架文件（hash 对比），同步依赖的 Skill 到最新（符合 SemVer 的 patch/minor）。
  6. 若用户修改过某脚手架文件且远程也有变更，生成到 `.skillhub/conflicts/` 供手动合并。
  7. 更新本地 lock 文件。
- 异常路径：
  1. 当前目录无 lock 文件 → 提示“当前项目不是由 skillhub template 初始化的，无法更新”。
  2. `--version` 参数不符合规范或不存在 → 提示“指定版本不存在或不合法”。
  3. Skill 发生 Major 变更 → 不自动更新该 Skill 的 resolved 版本，但发出系统通知告知用户或模板作者。
  4. 网络断开/下载失败 → 中止更新，保持原有文件不变并报错“连接超时”。

## 4. 页面结构
- 页面布局：无 Web UI 页面，主要在终端展现交互和 `outdated` 信息的打印；Web 端详情页会展示版本历史。
- 关键区域：
  - 终端的变更概览输出区（如 Git 状态的 diff 颜色标识）。
  - 更新确认提示（Y/n 交互）。
  - 冲突处理指引信息打印（如何查看 `.skillhub/conflicts/`）。
- 状态流转：检查版本 -> 计算变更/Hash比对 -> 下载更新 -> 冲突生成 -> 结束

## 5. 输入输出

### 5.1 输入
| 场景 | 输入 | 说明 |
|------|------|------|
| 检查落后版本 | `outdated` 命令 | 用户请求比对本地与远端的最新版本差异 |
| 执行更新命令 | `update` 与可选的 `[--dry-run]` | 用户决定进行版本同步操作或预览更新影响 |
| 冲突处理确认 | 手动解决 | 修改代码后手动删除或保留 `.skillhub/conflicts/` 中对应文件 |

### 5.2 输出
| 场景 | 输出 | 说明 |
|------|------|------|
| 更新结果预览 | 变更文件列表 | 通过颜色（绿加、黄改、红删）打印预期的变更集 |
| Major 警告 | 站内或群消息通知 | 针对有重大断裂更新的依赖，提示模板作者或项目维护者 |
| 解决提示 | 冲突生成日志 | 提示“X 个文件已自动合并，Y 个文件存在冲突存入 .skillhub/conflicts” |
